FTL 짬짬이 마스터

1. FTL이란 무엇인가?

NAND 플래시 메모리는 HDD나 RAM과 달리 '덮어쓰기(Overwrite)'가 불가능합니다. 무조건 지우고(Erase) 다시 써야 합니다. 게다가 읽기/쓰기는 페이지(Page) 단위로, 지우기는 블록(Block) 단위로 이루어집니다.

이러한 하드웨어적 한계를 소프트웨어적으로 가려주어, 호스트(PC)가 마치 일반 하드디스크처럼 편하게 쓸 수 있게 해주는 펌웨어 계층이 바로 FTL(Flash Translation Layer)입니다.

[ Host (OS / File System) ] ⬇ (논리적 주소 LBA) ================================== [ FTL (펌웨어) ] 1. Mapping 2. GC 3. Wear Leveling ================================== ⬇ (물리적 주소 PBA) [ NAND Flash Memory (물리적 하드웨어) ]

2. 맵핑 (Address Mapping)

핵심 기능 1

호스트가 요구하는 논리 주소(LBA)를 NAND 메모리의 실제 물리 주소(PBA)로 변환하는 테이블을 관리합니다.

덮어쓰기가 안 되기 때문에, 데이터가 수정되면 기존 데이터를 무효화(Invalid) 처리하고 새로운 빈 공간에 데이터를 쓰고(Valid) 맵핑 테이블을 갱신합니다.

호스트: "LBA 1번(문서.txt) 수정해줘!" [맵핑 테이블] LBA 1 ---> (과거) Block 10, Page 0 (Invalid ❌) ---> (현재) Block 12, Page 2 (Valid ✅)

3. 가비지 컬렉션 (Garbage Collection, GC)

핵심 기능 2

데이터가 수정될 때마다 ❌ 무효화(Invalid)된 찌꺼기 데이터가 쌓입니다. 빈 공간이 부족해지면, 여러 블록에 흩어진 ✅ 유효(Valid) 데이터만 모아서 새로운 블록으로 이사(Copy)시키고, 기존 블록들을 통째로 지워서(Erase) 빈 블록(Free Block)을 확보하는 작업입니다.

면접 포인트: GC가 발생하면 NAND에 읽기/쓰기 작업이 폭증하여 시스템 응답 속도(Latency)가 급격히 떨어집니다. 이를 최적화하는 것이 FTL 스케줄링의 핵심입니다.

[Block A] : ❌ ❌ ✅ ❌ [Block B] : ❌ ✅ ❌ ❌ ⬇ (GC 발동: 유효 데이터만 복사) [Block C] : ✅ ✅ 빈 빈 빈... (새로운 Free Block에 이사) ⬇ (기존 블록 지우기) [Block A], [Block B] ➡ 완전 초기화 (Free Block으로 재탄생)

4. 웨어 레벨링 (Wear Leveling)

핵심 기능 3

NAND 플래시의 각 블록은 지우기(Erase) 가능 횟수에 수명이 정해져 있습니다. 특정 블록만 자주 지우고 쓰면 그 블록이 망가져(Bad Block) SSD 전체 수명이 줄어듭니다.

따라서 특정 블록만 혹사당하지 않도록, 데이터를 플래시 메모리 전체에 골고루 분산시켜서 기록하는 수명 평준화 기술입니다.

[Block 1] 지움 횟수: 1000번 (혹사 당함 🥵) [Block 2] 지움 횟수: 10번 (쉬고 있음 😴) ⬇ (웨어 레벨링 발동) 자주 변하는 데이터(Hot Data)를 [Block 2]로 이동! 수명을 골고루 맞춘다!

5. 오버 프로비저닝 (Over-Provisioning, OP)

핵심 기능 4

가비지 컬렉션(GC)이나 웨어 레벨링, 배드 블록 대체를 원활하게 수행하기 위해 사용자에게는 숨겨둔 예비 여유 공간입니다. (예: 256GB SSD에 실제로는 275GB 낸드가 들어있음)
