1. NAND 플래시, 초등학생도 이해하는 3가지 핵심 비유

플래시 메모리가 처음이라도 전혀 걱정하실 필요 없습니다. 복잡한 반도체 양자역학 수식 대신, 일상적인 직관과 18년 임베디드/센서 공학적 감각에 빗대어 원리부터 단숨에 꿰뚫어 보겠습니다.

💡 비유 1. 전자를 가두는 '초미세 유리병(트랩)'과 '물높이 측정기'

NAND 플래시의 1개 셀은 전자를 가두는 뚜껑 달린 작은 유리병(Si3N4 질화막 트랩)과 같습니다.

  • 병이 비어 있을 때 (Erase 상태): 전자가 없으므로 아래쪽 도로(채널)에 전기가 콸콸 잘 통합니다. 디지털 신호로는 '1'로 읽습니다.
  • 병에 전자를 채웠을 때 (Program 상태): 음(-)전하를 띤 전자들이 도로 위를 꽉 막고 있어서, 전기를 통하게 하려면 게이트에 아주 높은 전압(문턱 전압, Vth)을 걸어야만 간신히 도로가 열립니다. 따라서 평소에는 전류가 차단되어 '0'으로 읽습니다.
  • 📌 센서 엔지니어링 브릿징: 마치 CMOS 이미지 센서(CIS)의 픽셀 포토다이오드에 빛(광자)이 들어가 전하가 축적되면 전위(전압)가 변하듯이, 낸드 셀 역시 트랩에 전자를 얼마나 채워 넣었느냐에 따라 문턱 전압(Vth)이 달라지는 원리입니다!
[ 전자가 비어 있을 때 (Erase 상태: '1') ] Control Gate (0V) ─────── [ 빈 트랩 유리병 ] ─────── 채널 도로: 전기가 저항 없이 콸콸 통함! (Vth 낮음) ➔ 데이터 '1' [ 전자를 채웠을 때 (Program 상태: '0') ] Control Gate (높은 전압을 걸어야 열림!) ─────── [ e- e- e- 전자 꽉 참 ] ─────── 채널 도로: 전자들이 전기장을 가로막아 전류 차단! (Vth 높음) ➔ 데이터 '0'
핵심 제약 1

2. 왜 덮어쓰기(Overwrite)가 안 되는가?

RAM이나 하드디스크(자성체)는 그냥 위에 덮어쓰면 되는데, 왜 낸드는 덮어쓰기가 안 될까요?

종이와 표백제 비유

NAND에 데이터를 쓰는 것은 '지워지지 않는 특수 펜으로 종이에 글씨를 쓰는 것'과 같습니다. 이미 잉크(전자)가 묻어 있는 종이 위에 다른 글씨를 덮어쓰면 새까맣게 번져서 판독할 수 없습니다.

따라서 반드시 표백제(고전압 20V 소거)를 부어 종이를 완전히 백지(Erase, 데이터 1)로 되돌린 후에만 새 글씨를 쓸 수 있습니다. 이것이 바로 FTL이 탄생하게 된 No In-Place Update의 물리적 이유입니다.

핵심 제약 2

3. 왜 지우기는 블록, 읽기/쓰기는 페이지인가?

왜 수정은 4KB/16KB 단위인데, 지우기는 수백 배 큰 16MB 블록 단위일까요?

크리스마스 트리 전구 직렬 연결 비유

NAND는 집적도를 극대화하기 위해 64~128개의 셀을 한 가닥의 전선에 전구처럼 줄줄이 직렬(String)로 꿰어 놓았습니다.

  • 읽기/쓰기 (Page 단위): 특정 전구 한 줄(워드라인)에만 전압을 걸어 신호를 넣고 뺍니다.
  • 지우기 (Block 단위): 전자를 뺄 때는 바닥 기판(P-Well) 전체에 20V 고전압을 통째로 걸어야 하므로, 기판을 공유하는 수천 개의 직렬 줄(블록 전체)이 한꺼번에 일괄 표백됩니다. 4KB 하나만 콕 집어서 지울 수가 없는 구조입니다!

Operation Mechanism

2. Fowler-Nordheim (FN) 터널링

NAND 플래시는 셀을 프로그램(쓰기)하고 소거(지우기)할 때 Fowler-Nordheim (FN) 양자 터널링 방식을 사용합니다.

프로그램(Program) 동작 원리

Control Gate에 높은 양전압(Vpgm ≈ +15V ~ +20V)을 인가하고 채널을 0V(접지)로 유지하면, 강한 수직 전기장이 형성되어 채널의 전자가 얇은 터널 산화막의 삼각 전위 장벽을 뚫고 트랩 층(Si3N4)으로 주입됩니다. 결과적으로 문턱 전압(Vth)이 양(+)의 방향으로 상승합니다.

소거(Erase) 동작 원리

기판(P-Well)에 고전압(Verase ≈ +20V)을 걸고 Control Gate를 0V로 접지합니다. 트랩 층에 갇혀 있던 전자들이 기판으로 일제히 빠져나가며, 셀의 Vth는 음수(Negative, 보통 -1V ~ -3V)의 소거 상태(Erase State)로 복원됩니다.

String Architecture

3. NAND Cell String 직렬 연결 구조

NAND 플래시의 핵심적인 구조는 셀들이 비트라인(Bitline)과 소스라인(Source Line) 사이에 직렬(In Series)로 연결되어 있다는 점입니다.

Bitline (BL) │ [ String Select Line (SSL) Transistor ] │ [ Cell WLn ] ── Vpass (6~7V) 도통 [ Cell ... ] ── Vpass (6~7V) 도통 [ Cell WL2 ] ── Vread (판독 전압 인가!) [ Cell WL1 ] ── Vpass (6~7V) 도통 [ Cell WL0 ] ── Vpass (6~7V) 도통 │ [ Ground Select Line (GSL) Transistor ] │ Common Source Line (CSL)

판독(Read) 메커니즘: 선택된 WL2 셀의 데이터를 읽기 위해, 나머지 모든 비선택 WL(WL0, WL1, WL3..WLn)에는 Vpass (약 6~7V)의 고전압을 걸어 데이터와 상관없이 무조건 켜지게 만듭니다. 그 후 WL2에 판독 전압(Vread)을 걸어 비트라인에 전류가 흐르면 '1', 차단되면 '0'으로 판독합니다.

Cell Density

1. 셀 레벨 발전 (SLC, MLC, TLC, QLC, PLC)

1개의 물리적 메모리 셀에 몇 비트의 정보를 저장하느냐에 따라 셀 레벨이 결정됩니다. 비트 수가 1씩 증가할 때마다 구분해야 하는 문턱 전압(Vth) 상태의 수는 2의 거듭제곱(2ⁿ)으로 급증합니다.

타입셀당 비트전압 상태 수상태 구분P/E Cycle 수명신뢰성 및 특징
SLC (Single Level)1 bit2개 (2¹)Erase, P1~100,000 회초고속, 극저지연, 엔터프라이즈 캐시/저널용
MLC (Multi Level)2 bit4개 (2²)E, P1, P2, P3~3,000 ~ 10,000 회레거시 고신뢰성 SSD
TLC (Triple Level)3 bit8개 (2³)E, P1 ~ P7~1,000 ~ 3,000 회현재 전 세계 메인스트림 SSD의 85% 이상
QLC (Quad Level)4 bit16개 (2⁴)E, P1 ~ P15~500 ~ 1,000 회대용량 아카이빙/데이터센터 스토리지
PLC (Penta Level)5 bit32개 (2⁵)E, P1 ~ P31~수백 회 미만초고밀도 연구 진행 중 (노이즈 마진 극소)
⚠️ Vth 전압 윈도우 한계와 마진 축소의 딜레마

NAND 셀의 물리적 최대 내압 한계로 인해 쓸 수 있는 총 전압 범위는 약 5V~6V로 고정되어 있습니다. 이 좁은 전압 창 안에 SLC는 2개, TLC는 8개, QLC는 16개의 상태를 우겨넣어야 하므로, 상태 간 간격(Noise Margin)이 밀리볼트(mV) 단위로 좁아져 미세한 전하 누설이나 간섭에도 비트 에러(RBER)가 폭증하게 됩니다.

Program Algorithm

2. ISPP (Incremental Step Pulse Programming)

NAND는 셀에 전압을 한 번에 세게 걸면 전자가 과도하게 주입되어 목표 전압을 초과(Over-programming)하므로, ISPP 계단식 펄스 알고리즘을 사용합니다.

Program Voltage (Vpgm) ▲ │ ┌─┐ ┌─┐ │ │ │ Verify Pass? │ │ │ ┌─┐ │ │ (PV1 검증) │ │ │ │ │ │ │ │ │ │──┴─┴───┴─┴───────────────┴─┴───▶ Time Pulse1 Pulse2 (+ΔVispp) Pulse3 (+ΔVispp)
  • 스텝 전압 (ΔVISPP): 펄스마다 전압을 약 0.2V~0.4V씩 계단식으로 상승 인가.
  • Program Verify (PV): 펄스 직후 목표 전압에 도달했는지 확인. 도달한 비트는 비트라인을 Vcc로 올려 추가 프로그래밍을 차단(Inhibit).
  • 카메라 렌즈 조절 비유: 마치 오토포커스(AF) 렌즈를 맞출 때 스텝 모터를 한 번에 돌리지 않고 펄스를 톡톡 주며 콘트라스트 피크를 찾는 피드백 제어와 완벽히 동일합니다.
Page Mapping

3. Gray Code & Multi-Pass (Foggy-Fine) Program

1개 셀에 3비트(TLC)가 들어갈 때, 이 3개 비트는 동일한 페이지에 묶이지 않고 Lower Page, Middle Page, Upper Page라는 완전히 독립된 3개의 논리 페이지로 분산 매핑됩니다.

왜 Gray Code를 사용하는가?

인접한 Vth 전압 상태 간에 오직 1비트만 차이가 나도록 코드를 배치(예: 111 ➔ 110 ➔ 100 ➔ 101...)합니다. 이렇게 하면 Vth 전압이 노이즈로 인해 이웃 상태로 살짝 넘어가더라도 최대 1비트의 에러만 발생하여 하드웨어 ECC(LDPC) 디코딩 부담을 최소화합니다.

Multi-Pass (Foggy-Fine) Program

인접 셀 간 기생 커패시턴스 간섭을 줄이기 위해, 먼저 대략적인 거친 전압으로 프로그래밍(Foggy Step)한 뒤, 인접 워드라인이 프로그래밍된 후 미세 정밀 전압(Fine Step)으로 최종 목표치까지 끌어올립니다.

3. CUA vs CBA (웨이퍼 하이브리드 본딩) 혁신

NAND 칩의 비트 밀도를 비약적으로 높이기 위한 주변 회로(Peri) 배치 기술의 진화입니다.

1단계: CUA (Circuit Under Array) / PUC

동일한 실리콘 웨이퍼 기판 위에 Row/Col 디코더와 펌프 회로를 먼저 만들고, 그 위에 3D 셀을 쌓는 방식입니다. 그러나 고전압 고열 3D 낸드 열처리 공정 때문에 하부 CMOS 트랜지스터의 고성능화에 제약이 따르는 한계가 있었습니다.

2단계: CBA (CMOS Directly Bonded to Array) - BiCS8 표준

로직 CMOS 웨이퍼와 3D 낸드 메모리 셀 웨이퍼를 완전히 분리하여 각각 가장 진보된 최적 공정 노드에서 제조한 뒤, 웨이퍼 상태에서 Cu-to-Cu(구리 대 구리) 다이렉트 하이브리드 본딩으로 결합합니다. (스마트폰 카메라 모듈의 Stacked CIS 센서와 정확히 같은 원리입니다!)

  • Dual-Plane / Quad-Plane 동시 동작: 서로 다른 플레인에 위치한 동일한 Row Address의 페이지를 동시에 읽거나(Multi-Plane Read) 동시에 쓸(Multi-Plane Program) 수 있어 낸드 내부 대역폭을 2~4배 확장합니다.
  • Multi-Plane 동작 제약: 커맨드 발행 시 모든 플레인이 동일한 페이지 오프셋을 공유해야 하는 어드레스 제약 조건이 따릅니다.

Reliability Failure 1

1. Data Retention & 아레니우스 모델

전하 트랩 층에 갇힌 전자가 시간이 흐름에 따라 열 에너지에 의해 절연 산화막을 뚫고 기판으로 자연 방전되는 현상입니다. 결과적으로 문턱 전압(Vth)이 낮은 쪽(좌측)으로 이동합니다.

온도와 아레니우스(Arrhenius) 가속 수명 방정식

보관 온도가 10°C 상승할 때마다 Retention 수명은 약 2배씩 급감합니다. JEDEC 표준은 활성화 에너지(Ea ≈ 1.1 eV) 기반으로 고온 챔버 가속 시험(HTOL / Aging)을 통해 드라이브의 전원 차단 상태 1년/3년 데이터 보존을 검증합니다.

Reliability Failure 2

2. Read Disturb 메커니즘

특정 워드라인을 읽을 때, 같은 스트링의 다른 모든 비선택 셀들에 인가되는 Vpass (약 6~7V) 전압이 원인입니다.

소프트 프로그램(Soft Program) 현상

Vpass는 읽기를 위해 무조건 켜지도록 가하는 전압이지만, 수십만 번 반복 인가되면 미세한 터널링이 발생하여 비선택 셀의 트랩 층으로 전자가 서서히 유입됩니다. 결과적으로 문턱 전압(Vth)이 높은 쪽(우측)으로 밀려나며 인접 상태와 충돌합니다.

Reliability Failure 3

3. Program Disturb & Self-Boosting 메커니즘

선택된 워드라인에 20V 고전압(Vpgm)이 인가될 때, 쓰기를 원치 않는 스트링의 셀(Inhibited Cell)에 우발적으로 전자가 주입되는 결함입니다.

Self-Boosting 기법의 진화
  • Basic Self-Boosting (BSB): SSL을 닫아 채널을 플로팅시킨 후 비선택 WL의 Vpass 전압과의 정전용량 결합으로 채널 전체를 8~10V로 균일 승압하여 전압 차를 축소.
  • Local Self-Boosting (LSB): 선택된 WL 양옆의 인접 WL에 0V를 인가하여 채널을 국소적으로 고립(Isolation)시킴으로써 선택 셀 바로 아래 채널만 집중적으로 승압.
  • Erased-Area Self-Boosting (EASB): 이미 프로그래밍된 셀 영역과 아직 비어있는 Erase 영역 사이의 채널 경계에서 발생하는 전하 누설을 차단하기 위해 선택 WL 직전 WL에 0V를 걸어 분리하는 고급 스킴.
Reliability Failure 4

4. Cell-to-Cell Coupling & 산화막 마모

  • Parasitic Capacitive Coupling: 이웃 셀에 전자가 주입되면 기생 커패시턴스로 인해 이미 쓰여진 인접 셀의 겉보기 Vth가 덩달아 상승하는 현상. (순차적 WL 프로그래밍 규칙으로 방어).
  • Endurance 열화 & SILC (Stress-Induced Leakage Current): P/E Cycle이 반복되면서 터널 산화막 격자 결함(Traps)이 생성되어 누설 전류가 폭증하고 결국 절연 파괴(Breakdown)로 런타임 배드 블록 발생.

Advanced Algorithm

2. Valley Search (계곡 탐색) & Predictive Vref 알고리즘

전통적인 Read Retry는 하드코딩된 RRT(Read Retry Table)를 1번부터 15번까지 순차 대입하므로 최악의 경우 수 밀리초(ms)의 심각한 읽기 지연(Tail Latency)이 발생합니다. 최신 고성능 SSD 펌웨어는 지능형 계곡 탐색(Valley Search)을 사용합니다.

🔍 Valley Search 원리

인접한 두 문턱 전압(Vth) 분포가 겹치는 영역의 비트 반전 빈도를 실시간 카운트하여, 미분 기울기(d(Error)/dV = 0)가 0이 되는 극솟값(Valley)을 이분 탐색(Binary Search)이나 Proximity Search로 수 스텝 내에 고속 수렴시킵니다. (마치 영상 처리에서 Otsu 이진화 임계값을 찾는 히스토그램 계곡 탐색과 수학적으로 완벽히 동일합니다!)

🧠 Predictive Local Offset Caching

동일 블록 내의 인접 워드라인(WL)들은 제조 공정 산포와 열 이력(Retention), Read Disturb 스트레스가 매우 유사합니다. 특정 WL에서 산출된 최적 Vref 오프셋을 컨트롤러 캐시에 보관하고 이웃 페이지 읽기 시 초기 기준 전압으로 선제 적용하여 재시도 횟수를 80% 이상 단축합니다.

Hardware/Firmware Boundary

3. Flash Memory Controller (FMC)와 FTL 분리

펌웨어 코어가 낸드 핀을 직접 비트뱅잉(Bit-banging)하면 성능이 나지 않습니다. 현대 SSD 컨트롤러는 하드웨어 FMC (Flash Memory Controller) 시퀀서를 둡니다.

  • Command Descriptor 큐잉: FTL은 메모리에 읽기/쓰기 커맨드 디스크립터만 큐잉하고, FMC 전용 하드웨어 엔진이 Toggle/ONFI 프로토콜 신호를 나노초 단위로 자동 생성.
  • Hardware Flash DMA: 수신된 낸드 데이터를 CPU 개입 없이 컨트롤러 SRAM/DRAM 및 LDPC ECC 디코더로 직통 스트리밍.
Factory Defect Handling

4. Factory Bad Block (FBBM) & Defect Column 리맵핑

  • Factory Bad Block Marker: 공장 출하 시 웨이퍼 검사에서 불합격된 블록은 첫 번째 또는 마지막 페이지의 스페어 영역 특정 바이트(예: 1st Byte)에 00h 비트를 기록하여 표시합니다. 펌웨어는 첫 부팅 시 절대 이 블록을 지우지 않고 스캔하여 초기 배드 블록 테이블을 구축해야 합니다.
  • Column Defect Replacement: 낸드 다이 내부에 예비 비트라인 컬럼(Spare Columns)을 두고 결함 비트라인을 온칩 퓨즈로 치환하여 단일 다이 수율을 방어합니다.

Q1. "낸드 플래시 펌웨어를 직접 다뤄보지 않았는데, 미디어 엔지니어링 팀을 어떻게 기술 리드할 수 있는가?"

[모범 답변]: "낸드 미디어 엔지니어링의 본질은 결국 '아날로그 실리콘 소자의 비선형적 노이즈(전압 이동, 온도, 열화)를 하드웨어 타이밍 동기화와 디지털 피드백 알고리즘으로 보정하여 완벽한 신뢰성을 이끌어내는 시스템 제어 공학'입니다. 저는 삼성전자에서 CMOS 이미지 센서의 서브밀리초 노출 타이밍을 실리콘 회로와 직접 동기화하고, 18년간 DSP/가속기 레지스터 직접 제어와 40만 프레임 Aging 무결점 검증을 완수한 경험이 있습니다. 낸드 물리 특성을 소프트웨어 파라미터로 추상화하고 FMC 시퀀서를 최적화하는 데 즉각적인 리더십을 발휘할 수 있습니다."

Q2. "TLC/QLC 낸드에서 P/E 사이클 마모로 RBER이 치솟을 때, Valley Search 알고리즘을 펌웨어에 어떻게 탑재하겠는가?"

[모범 답변]: "고정된 RRT 순차 탐색 대신, 2단계 하이브리드 탐색을 적용하겠습니다. 첫째, 동일 블록 내 인접 WL의 최근 성공 Vref를 캐싱하는 Predictive Local Offset Caching을 통해 80% 이상의 읽기를 1회에 성공시킵니다. 둘째, 캐시 미스 시에는 에러 비트 수의 2차 미분 기울기 기반 이분 탐색(Binary Valley Search)을 수행하여 단 2~3회 시도 만에 Vopt 극솟점으로 수렴시키고, 복구 즉시 Read Reclaim 워커를 깨워 안전 블록으로 데이터를 이주시킵니다."

Q3. "BiCS8 218단에 적용된 CBA(CMOS Directly Bonded to Array) 기술이 컨트롤러 펌웨어 설계에 주는 영향은?"

[모범 답변]: "CBA는 로직 웨이퍼와 셀 웨이퍼가 분리 제조되어 I/O 속도가 최대 3.2~4.8 Gbps로 비약적으로 향상되었습니다. 펌웨어 관점에서는 낸드 버스 전송 시간(tBus)이 극적으로 줄어들어 tPROG 및 tR과의 비대칭성이 더욱 심화됩니다. 따라서 FMC의 커맨드 디스크립터 큐잉과 Dual-Plane/Quad-Plane 인터리빙을 더욱 공격적으로 스케줄링하고, Cache Program/Read 오버랩을 극대화하여 버스 유휴 시간을 없애는 파이프라인 설계가 필수적입니다."

Q4. "85°C 고온 환경에서 Data Retention 열화로 인한 셀 전하 누설을 펌웨어 관점에서 어떻게 능동 방어하겠는가?"

[모범 답변]: "컨트롤러 온칩 서멀 센서와 연동하여 동작 온도를 실시간 누적 모니터링하는 온도 가중치 타이머(Temperature-Weighted Retention Tracker)를 구동합니다. 고온 누적 시간이 임계치에 도달하면 유휴(Idle) 시간에 백그라운드 Retention Scan을 선제 가동하여, Vth가 좌측으로 이동한 블록을 감지하고 LDPC UECC가 터지기 전에 미리 새 블록으로 복사하는 Data Refresh를 스케줄링합니다."

Q5. "공장에서 출하된 Initial Bad Block(FBBM)과 사용 중 발생하는 Runtime Bad Block을 구별하여 처리하는 원칙은?"

[모범 답변]: "초기 공장 배드 블록(FBBM)은 웨이퍼 결함으로 스페어 영역 특정 바이트에 마킹되어 있으므로, 펌웨어 최초 부팅 시 절대로 Erase 명령을 내리지 않고 스캔하여 비휘발성 BBT 메타 블록에 영구 등록합니다. 반면 런타임 배드 블록은 P/E 수행 중 낸드 Status Register(70h)가 Fail을 반환할 때 검출되며, 즉시 해당 블록을 BBT에 격리 등록하고 예비 블록 풀(Reserve Pool)의 정상 블록으로 쓰기 데이터를 즉각 리다이렉트합니다."

Python Engineering Tool

5. Python 기반 NAND 물리 특성화 & RBER Shmoo 분석 스크립트

Senior Staff Firmware Engineer 직무에서 요구하는 Python 객체 지향 데이터 분석 및 특성화 파이프라인의 실제 구현 예제입니다. 낸드 테스트 벤치에서 수집된 전압별 RBER 데이터를 가공하여 최적의 Vref와 동작 윈도우를 도출합니다.

# Python NAND Characterization & Optimal Vref Finder (Senior Staff Firmware Framework) import numpy as np class NandCharacterizer: def __init__(self, die_id: int, block_id: int): self.die_id = die_id self.block_id = block_id self.sweep_data = {} # vref_offset -> raw_bit_error_count def record_sweep_point(self, vref_mv: int, bit_errors: int, total_bits: int = 131072): rber = bit_errors / total_bits self.sweep_data[vref_mv] = rber def find_optimal_vref_valley(self) -> tuple[int, float]: """2차 다항식 피팅(Polynomial Fitting)을 통한 최저 계곡(Valley) 탐색""" offsets = np.array(list(self.sweep_data.keys())) rbers = np.array(list(self.sweep_data.values())) # Fit quadratic curve: RBER = a*V^2 + b*V + c poly = np.polyfit(offsets, rbers, 2) v_opt = -poly[1] / (2 * poly[0]) # d(RBER)/dV = 0 min_rber = np.polyval(poly, v_opt) return int(round(v_opt)), float(min_rber) # 실제 사용 예시: char = NandCharacterizer(die_id=0, block_id=128) for v in range(-20, 21, 5): errors = int(120 + 0.45 * (v - (-5))**2) char.record_sweep_point(vref_mv=v, bit_errors=errors) opt_v, opt_rber = char.find_optimal_vref_valley() print(f"[Analysis] Optimal Vref Offset: {opt_v} mV, Predicted Min RBER: {opt_rber:.2e}")
